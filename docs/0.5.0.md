# CAPT v0.5.0 — CAPI v1beta2 対応 作業メモ（WIP）

## 概要
- 目的: CAPT を CAPI v1beta2 契約へ移行しつつ、v1beta1 を served 継続、v1beta2 を storage に設定。
- 現状: v1beta2 型・CRD の導入と双方向変換（Hub&Spoke）の基盤は実装済み。変換 Webhook（CRD/kustomize・Service 追加済み、manager 登録は保留）/契約ラベル（付与済み）/テスト類は未完了（下記 TODO）。

## 完了した作業（Done）
- API 追加（Hub）
  - `api/v1beta2` に以下を追加（各型に `+kubebuilder:storageversion` と Hub マーカー）：
    - `CAPTCluster`/`CAPTClusterTemplate`
    - `CaptMachine`/`CaptMachineTemplate`/`CaptMachineSet`/`CaptMachineDeployment`
    - `CAPTControlPlane`/`CAPTControlPlaneTemplate`
    - `WorkspaceTemplate`/`WorkspaceTemplateApply`
- 変換（Spoke）
  - `api/v1beta1` 側に双方向コンバージョンを実装：
    - `CAPTCluster`（`api/v1beta1/captcluster_conversion.go`）
    - `CAPTControlPlane`（`api/controlplane/v1beta1/captcontrolplane_conversion.go`）
- CRD 生成と versions の並列化
  - Makefile の生成ラインを `./api/...` に拡張。`make clusterapi-manifests` により、各 CRD に `v1beta1 (served:true, storage:false), v1beta2 (served:true, storage:true)` を反映。
  - 生成済み CRD（抜粋）:
    - `config/clusterapi/infrastructure/bases/infrastructure.cluster.x-k8s.io_captclusters.yaml`（`v1beta2.storage: true`）
    - 同様に Machine 系 / ControlPlane 系 / Workspace 系 CRD を出力
- マネージャ組み込み
  - `cmd/main.go` に v1beta2 の `AddToScheme` を追加（v1beta1 と併存）。
- DeepCopy 生成
  - `make generate` 済み。v1beta2 型の DeepCopy が揃っていることを確認。
- clusterctl メタデータ
  - `metadata.yaml` に `0.5 = v1beta2` が定義済み（最新の内容を採用）。
